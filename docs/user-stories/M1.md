# M1 Persistance des sessions et profil utilisateur

## Story 1

En tant que développeur, je veux reprendre une conversation d'un lancement précédent, afin de
continuer mon travail sans réexpliquer le contexte au modèle.

Critères d'acceptation :
- Chaque conversation est enregistrée ; `sensai sessions` les liste, de la plus récente à la plus
  ancienne, avec leur id, leur date et le premier message.
- `sensai chat --resume` reprend la session la plus récente : le modèle reçoit tout son historique.
- `sensai chat --resume <id>` reprend une session donnée ; les premiers caractères de l'id suffisent.
- Un id inconnu ou ambigu, ou l'absence de session, affiche une erreur claire et le code de
  retour 2, sans appeler le modèle.

## Story 2

En tant qu'utilisateur, je veux enregistrer une fois mes instructions et mes préférences (par
exemple « je travaille en Python », « allergique à la pénicilline »), afin que l'assistant en tienne
compte sans que je les répète.

Critères d'acceptation :
- `/profile instructions <texte>`, `/profile set <clé> <valeur>`, `/profile unset <clé>` et
  `/profile clear` modifient le profil ; `/profile` l'affiche.
- Le profil est envoyé au modèle comme message système à chaque tour, dès le tour suivant sa
  modification, et dans toutes les sessions suivantes, reprises ou nouvelles.
- Le profil n'est pas enregistré dans l'historique des messages.
- Une commande `/profile` invalide affiche l'aide sans modifier le profil.
