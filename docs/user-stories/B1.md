# B1 Functional CLI chatbot

## Story 1

As a developer, I want to chat with a local model from my terminal and see the answer as it is
generated, so that I get quick feedback without sending my code to a third-party service.

Acceptance criteria:
- The answer appears progressively, chunk by chunk, not as a single block.
- The model runs on my machine through the Ollama HTTP API: no remote service is called.
- A spinner is shown while the model has not produced text yet.
- The number of prompt and completion tokens is shown after each answer.

## Story 2

As a developer, I want the model to remember what I said earlier in the session and to choose
the model without editing code, so that I can have a real conversation and compare models.

Acceptance criteria:
- A follow-up question that refers to a previous turn is answered with that context.
- `sensai chat --model <name>` uses that model for the whole session.
- Without `--model`, the model comes from `configs/default.toml` or from the file given with
  `--config`.
- Ctrl-C during a generation stops it and returns to the prompt; the text already received is
  kept in the history.

## Story 3

As a developer, I want a clear message when Ollama or the model is unavailable or when I type
nothing, so that I know how to fix the problem instead of reading a stack trace.

Acceptance criteria:
- With Ollama stopped, an error names the server address and suggests how to start it; the chat
  stays open.
- With a missing model, the error names the model and suggests `ollama pull`; the chat stays
  open.
- An empty line does not call the model.
- Ctrl-D or `/exit` quits cleanly, with exit code 0.
