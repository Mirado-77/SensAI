# B1 Chatbot CLI fonctionnel

## Story 1

En tant que développeur, je veux discuter avec un modèle local depuis mon terminal et voir la
réponse s'afficher au fur et à mesure de sa génération, afin d'avoir un retour rapide sans envoyer
mon code à un service tiers.

Critères d'acceptation :
- La réponse apparaît progressivement, morceau par morceau, et non en un seul bloc.
- Le modèle tourne sur ma machine via l'API HTTP d'Ollama : aucun service distant n'est appelé.
- Un indicateur d'attente s'affiche tant que le modèle n'a pas produit de texte.
- Le nombre de tokens du prompt et de la réponse s'affiche après chaque réponse.

## Story 2

En tant que développeur, je veux que le modèle se souvienne de ce que j'ai dit plus tôt dans la
session et pouvoir choisir le modèle sans modifier le code, afin d'avoir une vraie conversation et
de comparer des modèles.

Critères d'acceptation :
- Une question qui fait référence à un tour précédent reçoit une réponse qui tient compte du
  contexte.
- `sensai chat --model <nom>` utilise ce modèle pendant toute la session.
- Sans `--model`, le modèle vient de `configs/default.toml` ou du fichier donné avec `--config`.
- Ctrl-C pendant une génération l'arrête et renvoie au prompt ; le texte déjà reçu est conservé
  dans l'historique.

## Story 3

En tant que développeur, je veux un message clair quand Ollama ou le modèle est indisponible, ou
quand je ne tape rien, afin de savoir comment corriger le problème au lieu de lire une trace
d'erreur.

Critères d'acceptation :
- Ollama arrêté : une erreur indique l'adresse du serveur et comment le démarrer, et le chat reste
  ouvert.
- Modèle absent : l'erreur nomme le modèle et suggère `ollama pull`, et le chat reste ouvert.
- Une ligne vide n'appelle pas le modèle.
- Ctrl-D ou `/exit` quitte proprement, avec le code de retour 0.
