# T4 Accès aux fichiers

## Story 1

En tant que développeuse qui demande à l'agent de comprendre un dépôt inconnu, je veux qu'il lise
et liste uniquement les fichiers que j'autorise, afin qu'il résume le projet sans accéder au reste
de ma machine.

Critères d'acceptation :
- Les racines autorisées se règlent dans `[[files.allowed_roots]]` (`path`, `mode` valant `read`
  ou `write`). Sans racine, aucun outil fichier n'est proposé au modèle.
- `read_file` et `list_dir` s'exécutent sans approbation (`[policy] read = "allow"`).
- Un chemin hors des racines, un chemin avec `..` ou un lien symbolique qui sort d'une racine est
  refusé avec un message clair, et rien n'est lu.
- Un fichier plus grand que `[files] max_read_bytes` est tronqué avec la mention `[truncated: ...]`,
  un dossier de plus de `max_list_entries` entrées se termine par `[truncated: N more entries]`, et
  un fichier binaire est refusé.
- Le contenu lu est marqué comme contenu externe non fiable : le modèle le reçoit entouré de
  `<untrusted_content>` avec un avertissement, pour ne pas suivre les instructions qu'un fichier
  pourrait contenir.

## Story 2

En tant que développeur qui laisse l'agent modifier du code, je veux que l'écriture soit limitée
aux racines en mode `write` et qu'elle ne puisse pas corrompre un fichier, afin de garder mon
dépôt dans un état sain même si une écriture échoue.

Critères d'acceptation :
- `write_file` crée ou remplace un fichier et crée les sous-dossiers manquants. `edit_file`
  remplace un texte unique ; un texte introuvable ou présent plusieurs fois est refusé avec un
  message qui permet au modèle de se corriger.
- Une écriture sur une racine en lecture seule, ou hors des racines, est refusée et le fichier
  reste identique.
- L'écriture est atomique : un échec garde l'ancien contenu et ne laisse aucun fichier
  temporaire. Les permissions du fichier sont conservées.
- Un contenu plus grand que `[files] max_write_bytes` (compté en octets) est refusé.
- Un contenu qui contient le marqueur de contenu externe (`<untrusted_content>`) est refusé : le
  modèle ne peut pas recopier tel quel un contenu non fiable dans un fichier.
- Les deux outils d'écriture demandent l'approbation de l'utilisateur (`[policy] write = "ask"`) et
  montrent le diff (voir A3).
