# R1 Recherche sémantique dans le code (RAG)

## Story 1

En tant que développeur, je veux indexer mon dépôt avec une commande, afin que l'assistant puisse
retrouver le code utile sans que je lui indique les fichiers.

Critères d'acceptation :
- `sensai index` découpe les fichiers texte des racines autorisées (`[files] allowed_roots`) en
  blocs de `[rag] chunk_lines` lignes qui se chevauchent de `[rag] overlap` lignes, les fait
  vectoriser par Ollama (`/api/embed`, modèle `[rag] embed_model`) et les enregistre en base.
- `sensai index <dossier>` n'indexe que ce dossier, qui doit être dans une racine autorisée ;
  sinon la commande affiche une erreur et renvoie le code 2.
- Les dossiers cachés (`.git`, `.venv`...), `node_modules`, `__pycache__`, `build`, `dist`, les
  fichiers binaires et ceux plus gros que `[files] max_read_bytes` sont ignorés.
- Relancer `sensai index` ne revectorise que les fichiers modifiés et retire de l'index les
  fichiers supprimés. La commande affiche `N files indexed (M chunks), U unchanged, D removed`.
- Ollama injoignable ou modèle d'embedding absent : message d'erreur, code de sortie 1.

## Story 2

En tant qu'utilisateur du chat, je veux que le modèle puisse chercher dans le code indexé, afin
d'obtenir des réponses fondées sur le vrai code avec la référence des lignes.

Critères d'acceptation :
- Quand l'index n'est pas vide et `[rag] enabled = true`, le chat propose l'outil `search_code`
  (visible dans `/tools`, risque `read`).
- `search_code` renvoie les `[rag] top_k` extraits les plus proches de la requête, chacun précédé
  de `chemin:début-fin (score x.xx)`, marqués comme contenu non fiable.
- Un extrait d'un fichier qui n'est plus dans une racine autorisée n'est jamais renvoyé.
- Une requête vide est une erreur renvoyée au modèle ; une panne d'Ollama aussi, sans arrêter le
  tour.
