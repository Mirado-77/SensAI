# T1 MCP

## Story 1

En tant que développeuse qui découvre un dépôt Python, je veux que l'assistant appelle de lui-même
un outil de navigation dans le code au milieu de sa réponse, afin qu'il s'appuie sur le contenu
réel des fichiers plutôt que de deviner.

Critères d'acceptation :
- Avec le serveur `sensai-mcp` déclaré dans `[[mcp.servers]]`, la bannière du chat annonce le
  nombre d'outils et `/tools` les liste avec leur niveau de risque.
- Quand le modèle demande `code__python_symbols` ou `code__find_references`, l'appel est exécuté,
  affiché (`tool> ...`), et le résultat est renvoyé au modèle qui continue sa réponse.
- Le résultat d'un outil MCP est marqué comme contenu non fiable : le modèle le reçoit comme des
  données, jamais comme des instructions.
- Un chemin hors de la racine donnée à `sensai-mcp --root` (`..`, chemin absolu, lien symbolique
  qui sort) est refusé avec une erreur lisible.

## Story 2

En tant qu'intégrateur, je veux brancher un serveur MCP existant par simple configuration, avec les
mêmes règles de sécurité que les outils natifs, afin d'étendre l'assistant sans toucher au code.

Critères d'acceptation :
- Ajouter un bloc `[[mcp.servers]]` (commande, arguments, risque) suffit : le serveur officiel
  `@modelcontextprotocol/server-filesystem` est lancé au démarrage et ses outils apparaissent sous
  le nom `fs__<outil>`.
- Le niveau de risque vient de la configuration, ou de l'indication `readOnlyHint` du serveur avec
  `risk = "auto"` ; la politique d'approbation s'applique ensuite comme pour un outil natif
  (une action `exec` demande une confirmation).
- Un serveur qui ne démarre pas ou refuse l'initialisation est signalé par un avertissement, et le
  chat démarre quand même avec les autres serveurs.
- Un serveur qui plante ou ne répond plus pendant un appel produit une erreur d'outil renvoyée au
  modèle, après le délai `[mcp] timeout_s`, sans bloquer le tour.
