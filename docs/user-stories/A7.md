# A7 Sélection de few-shots et comparaison de variantes de prompt

## Story 1

En tant que développeur qui utilise un petit modèle local, je veux que l'agent reçoive quelques
exemples de bonnes réponses proches de ma question, afin qu'il réponde dans le style attendu
(fichier cité, cause puis correction, réponse courte).

Critères d'acceptation :
- Les exemples sont des fichiers `configs/prompts/examples/*.toml` avec `id`, `question` et
  `answer`. Un exemple invalide ou un identifiant en double est signalé au démarrage du chat, qui
  s'arrête avec le code 2.
- Avec `[prompts] examples = N`, chaque tour envoie les `N` exemples qui partagent le plus de mots
  avec le message, juste après le prompt système, sous forme de messages utilisateur et assistant.
  Un exemple qui ne partage aucun mot n'est jamais envoyé ; `0` (le défaut) n'en envoie aucun.
- Les exemples ne sont jamais enregistrés dans la session : l'historique ne garde que les vrais
  échanges.
- L'événement `prompt.examples` journalise les identifiants des exemples envoyés, et la bannière
  du chat affiche le nombre d'exemples actifs.

## Story 2

En tant que développeur qui hésite entre deux variantes de prompt, je veux comparer leurs
rapports EV1 question par question, afin de n'activer une variante que si elle améliore vraiment
les réponses.

Critères d'acceptation :
- `make eval-quality ARGS="--examples N"` évalue la variante avec `N` exemples ; le rapport EV1
  indique la variante (`<version>@<sha> + N exemples`) et, pour chaque question, les exemples
  envoyés.
- `make eval-compare ARGS="A.json B.json"` affiche les deux variantes, les modèles, le score moyen
  et le score de chaque question, avec l'écart de B par rapport à A. Une question absente d'un
  rapport est marquée `-`.
- Un fichier absent, illisible ou qui n'est pas un rapport EV1 est signalé et la commande sort
  avec le code 2. Un rapport écrit avant A7 est lu comme une variante sans exemple.

## Tests

Les tests portent l'ID de la fonctionnalité avec `@pytest.mark.feature("A7")`.

- `tests/unit/test_fewshots.py` : chargement et sélection des exemples, envoi par le runtime sans
  enregistrement, événement, chat, variante enregistrée par EV1 et comparaison de deux rapports.
