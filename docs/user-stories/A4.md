# A4 Versionnage des prompts

## Story 1

En tant que développeur qui modifie le prompt système de SENSAI, je veux que chaque version soit
un fichier distinct et que je puisse revenir à la précédente en une commande, afin d'essayer une
nouvelle formulation sans risquer de casser la démo.

Critères d'acceptation :
- Les versions sont des fichiers `configs/prompts/system/<nom>.txt` ; `[prompts] system` choisit
  la version active (v2 par défaut).
- `sensai prompts` liste les versions avec leur empreinte et marque la version active d'un `*`.
- `sensai prompts diff v1 v2` affiche les lignes ajoutées et retirées entre deux versions.
- Le retour arrière se fait avec `sensai chat --prompt v1`, ou `/prompt v1` dans le chat, sans
  perdre l'historique de la session ; `/prompt` seul affiche la version active.
- Une version inconnue est refusée avec la liste des versions connues : le chat ne démarre pas
  (code 2), ou garde la version active si c'est `/prompt`.

## Story 2

En tant que développeuse qui doit choisir entre deux prompts, je veux comparer les versions sur
les tours réellement joués, afin de garder celle qui échoue le moins et consomme le moins.

Critères d'acceptation :
- Chaque tour enregistre `prompt_version` (`<nom>@<sha>`) dans l'événement `run.started` du
  journal ; un fichier modifié donne une nouvelle empreinte, donc une ligne à part.
- `sensai prompts stats` affiche, par version : nombre de tours, terminés, échoués, tokens moyens,
  durée moyenne, appels d'outils et erreurs d'outils.
- Le prompt de la version passe avant le profil (M1), qui reste appliqué à chaque tour.
- `[prompts] system = ""` n'envoie aucun prompt de base.
