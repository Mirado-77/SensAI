# T3 Recherche web sur la documentation

## Story 1

En tant que développeuse qui demande à l'agent comment utiliser une librairie, je veux qu'il
cherche sur le web la documentation officielle, afin de répondre avec les versions actuelles et
des liens vérifiables.

Critères d'acceptation :
- `make searxng` démarre une instance SearXNG locale sur `127.0.0.1:8080`, avec le format JSON
  activé (`docker/searxng/settings.yml`). Aucune clé d'API et aucun quota.
- L'outil `web_search` est proposé au modèle quand `[web] enabled = true`. Quand il est désactivé,
  il n'est pas proposé.
- Il renvoie jusqu'à `[web] max_results` résultats, chacun avec un titre, une URL et un extrait.
  Le texte est tronqué à `[web] max_result_chars` caractères.
- Le contenu renvoyé est marqué comme contenu externe non fiable : le modèle le reçoit entouré de
  `<untrusted_content>`.
- Si SearXNG ne répond pas, l'outil renvoie un message d'erreur qui indique `make searxng`, sans
  planter le tour.

## Story 2

En tant que développeuse qui veut des sources fiables, je veux limiter la recherche à certains
sites, afin que les réponses viennent de la documentation officielle et non de blogs.

Critères d'acceptation :
- `allowed_domains` ne garde que les résultats dont le domaine correspond (sous-domaines inclus).
- `blocked_domains` retire les résultats dont le domaine correspond (sous-domaines inclus).
- Utiliser les deux paramètres dans le même appel est refusé avec un message clair.
- Une requête de moins de 2 caractères est refusée sans appel réseau.
- Une réponse HTTP 403 de SearXNG est expliquée : le format JSON n'est pas activé.

## Tests

- `tests/unit/test_web_search.py` : format des résultats, filtres de domaines, bornes, erreurs,
  et proposition de l'outil selon la configuration. Les appels HTTP sont simulés avec `respx`.
