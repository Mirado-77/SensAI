# M4 Document d'état du projet

## Story 1

En tant que développeur qui travaille sur un bug avec l'agent, je veux qu'il tienne à jour un
document d'état séparé de la conversation (objectif, décisions, ce qui est fait, ce qui reste à
faire), afin de savoir où en est le travail sans relire tout l'historique.

Critères d'acceptation :
- Le modèle modifie le document avec l'outil `artifact_patch` : une section à la fois, choisie
  parmi `[artifact] sections`, avec l'opération `append` (ajoute une ligne) ou `replace` (réécrit
  seulement cette section). Les autres sections ne changent pas.
- Chaque modification demande l'approbation de l'utilisateur, avec la section et le texte. Un
  refus n'écrit rien.
- Une section inconnue, un texte qui ferait dépasser `[artifact] max_section_chars` ou un texte
  qui recopie un bloc de données externes est une erreur renvoyée au modèle, sans rien modifier.
- Chaque modification réelle émet l'événement `artifact.patched` (section, opération, taille) et
  est gardée avec son contenu avant et après dans la table `artifact_patches`.

## Story 2

En tant que développeur, je veux que l'agent voie ce document à chaque tour et que je puisse le
consulter, afin que le travail continue au bon endroit, y compris après un fork ou une reprise.

Critères d'acceptation :
- À chaque tour, le document non vide est envoyé au modèle après le prompt système, marqué comme
  données. Il n'est pas enregistré dans la session.
- Dans le chat, `/doc` affiche le document en Markdown, dans l'ordre des sections de la config.
  Un document vide l'indique ; avec `[artifact] enabled = false`, la commande indique que le
  document est désactivé et l'outil n'est pas proposé.
- `/fork <n>` crée une session qui part avec une copie du document ; l'historique des
  modifications reste dans la session d'origine.
- Le document est lié à la session : `sensai chat --resume` le retrouve.

## Tests

Les tests portent l'ID de la fonctionnalité avec `@pytest.mark.feature("M4")`.

- `tests/unit/test_artifact.py` : `patched`, store (sections, modification, historique, rendu,
  copie), note envoyée au modèle, outil (schéma, refus, événement, aperçu), ajout par le runtime
  sans enregistrement, `/doc`, modification approuvée dans le chat et copie au fork.
- `tests/unit/test_db.py` : migration `005_m4_artifact`.
